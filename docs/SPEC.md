# 人生チャート日記アプリ「MindStock」— 確定仕様書

*デザイン着手前の設計の拠り所。Figmaを開く前にこれを横に置く。*

---

## 1. コンセプト（一行で）

**ただ日記を書くだけで、人生が株価のローソク足チャートとして可視化され、「あの頃より今は成長している」を実感できるアプリ。**

普通の日記アプリとの決定的な違いは、書いた文章をAIが解析して「出来事の重要度」を判定し、人生の軌跡を一本のチャートとして描き続けること。ユーザーは重要度の判定作業から解放される。

---

## 2. 設計の最優先事項：継続のハードルを下げる

どんなに賢いアルゴリズムも、入力が続かなければ意味がない。日記アプリの最大の敵は三日坊主。だから全機能はこの問いに従う ——「これは入力のハードルを上げていないか？」

### 入力の3階層（負荷に応じて選べる）

| 階層 | ユーザーがやること | チャートへの反映 |
|---|---|---|
| しっかり | 普通に日記を文章で書く | AIが出来事を抽出し、複数の変動を算出。大きい出来事はベースラインも動かす |
| 軽め | 気分スライダー1つ（＋一言メモは任意） | その日の小さな揺れとして反映 |
| なし | 何もしない | 前の水準を維持して緩やかに継続。**空白は罰しない（＝平穏な日とみなす）** |

> **重要原則：** 一日空けても「途切れた」と感じさせない。空白＝悪、ではなく空白＝平穏。これが継続の生命線。

---

## 3. 入力フロー（コア体験）

```
日記を書く → AIが即座に採点 → その日のローソク足が自動反映（確認なし）
```

**基本フローに確認画面は挟まない。** 書いたら終わり。ユーザーは何もタップしない。これが最速・最低ハードルの形。

### 微調整はオプション機能（メインフローから完全に切り離す）

スライダーで出来事を確認・調整したい人だけ、後から**個別のエントリー画面／カレンダーから該当日を開く**ことで編集できる。仕様は以下（検証済みUI、ただしメイン導線には出さない）：

- AIが抽出した出来事を**カード**で並べる（1日3〜4枚程度）
- 各カードでできること：
  - **スライダー**で重みを直感的に調整（0〜10）
  - **プラス/マイナス**ボタンで方向を反転（AIの読み違え対策）
  - 右端に変動値がリアルタイム表示
- 出来事の種別を3つに分類（AIが自動判定）：
  - **日常**（一時的な揺れ）
  - **気分**（一時的な小さな揺れ）
  - **節目／マイルストーン**（比較的大きな点数として反映）
- 編集後、再計算してその日のローソク足を更新
- 「＋手動追加」でAIの見逃しも補完可能

> **原則：** 確認・微調整は「やりたい人だけやる」機能。書く→即反映、が9割のユーザーの体験になる。

### AI判定の注意点（実装で必ず守る）

1. AIが判定するのは**客観的な性質と重要度のレンジ**まで。本人の主観的な感じ方を勝手に決めない
2. 判定結果は原則そのまま反映するが、**後から編集できる余地は必ず残す**（完全にロックすると、ズレた時に「分かってない」と感じて離脱する）
3. 気分スライダーの値と、AIが文章から出した変動値の**スケールを揃える**（実装時の調整ポイント）
4. **基本フローは「書く→AI自動判定→即反映」のみ。数値の手動入力・確認は主経路から完全に外す**（面倒くさい作業をユーザーに強いない、が大原則）

## 4. チャートのロジック（確定方針・最終版）

### 採用モデル：AI委任型・足し算モデル

**レベルモデル（ベースライン水準移動）はパージ。** 理屈は綺麗だったが、水準が段階的に動く実装は「ガクンガクンする」不自然さが拭えず、構造も複雑になりすぎた。

最終的に採用するのは、**シンプルな足し算モデル**。ただし「イベントの点数付け」を機械的な固定テーブルでやるのではなく、**AIに文脈込みで判断させる**ことで、足し算だけでも自然な曲線を作る。

```
今日の値 ＝ 前日の値 ＋ 今日の出来事の点数の合計（AIが文脈判断して算出）
```

### AIが点数を出す時に織り込む要素（プロンプト設計の核）

数式でベースラインを動かすのではなく、**AIのスコアリング自体に以下を反映させる**：

1. **出来事自体の客観的重要度**（合格・失恋級の大きさをAIが判定）
2. **快楽順応（hedonic adaptation）**：直近の日記履歴をAIに渡し、似た出来事が続いていれば点数を意図的に下げる（例：「またバイトで褒められた」が3回目なら1回目より低く採点）
3. **損失回避**：同じ重要度でもネガティブな出来事はポジティブよりやや重めに採点する、とプロンプトに明記する

この設計の利点：
- 値の更新ロジックは単純な足し算のみ。実装が大幅に軽くなる
- ベースラインを強制的に動かす機構が無いので、**構造的にガクンガクンが起きない**
- 「賢い採点」の責任をAI側に寄せることで、数式のパラメータチューニング地獄を避けられる

### それでも残す調整パラメータ（最小限）

- **損失回避の強さ**：AIへの指示文の強度として調整（例：「ネガティブは1.3〜1.5倍重く見て採点して」）
- **日々のノイズ**：出来事が無い日でも乗る微小な揺れ。完全な水平線にならず人間らしくなる（これは数式側で足すだけでよい）

> **注：** 快楽順応や損失回避の「正確な効き具合」はAIの採点品質に依存する。唯一の正解係数を探すのではなく、AIへのプロンプトを実際の日記で試しながら調整していく前提。

## 5. 表示形式：ローソク足をメインに

折れ線では「その日の終値」一点しか表せない。コンセプト ——「いい事も悪い事もあった日」「マイナスを飛び越えて結局トータルでプラス」—— を表すには**ローソク足**が最適。

### 一本のローソクが持つ4つの値

- **始値**：その日の朝の水準（＝前日の終値）
- **高値**：その日のポジティブ出来事の点数（AI採点済み）を全部積み上げた最高到達点（上ヒゲ）
- **安値**：その日のネガティブ出来事の点数（AI採点済み）を全部積み上げた最低到達点（下ヒゲ）
- **終値**：始値＋その日の点数合計（＝プラスマイナス相殺後の着地点）

### 読み方

- **下ヒゲが長い** ＝ 辛いこともあったが持ち直した日。「マイナスを飛び越えてプラス」がこれ
- **上ヒゲ** ＝ 一度上がったが戻った日
- **大きい実体** ＝ 出来事が多く濃い日／**小さい十字（同事線）** ＝ 平穏な日

### 色のルール

- **緑（陽線）**：その期間トータルでプラス
- **赤（陰線）**：トータルでマイナス
- ※日本の株は赤が上だが、感情の文脈では「緑＝良い／赤＝悪い」が直感的なのでこちらを採用（変更可）

### 時間軸の切り替え（株アプリと同じ）

- **週足**：1本＝1週間。長期（数ヶ月〜1年）を俯瞰する時
- **日足**：1本＝1日。直近の細かい濃淡を見る時
- **移動平均線**を重ねて長期トレンドを表示
- **ピンチズーム・横スクロール対応**：特定の時期（例：学生時代のどん底）に拡大して、当時の変動幅を直接見られるようにする。落差の自分比較などの専用指標は用意せず、この操作性でカバーする

## 6. 「成長を実感する」ための機能

単純な右肩上がりは嘘くさく、辛い時期を否定してしまう。本当に欲しいのは ——「辛い時期はちゃんと谷として刻まれている。でもそこから今の自分がどれだけ離れたかが見える」。谷があるからこそ成長が見える。**谷を消さない。**

採用する3つの仕組み：

### (1) 過去の自分との多重比較
今日の値を「1ヶ月前」「半年前」「1年前」の自分と比較表示。「昨日よりはマイナスだけど、半年前のどん底からは大きくプラス」が一目で分かる。

### (2) チャートのズーム・スクロールで相対比較する
**別立てのドローダウン専用チャートはパージ。** メインのローソク足チャートを拡大縮小・スクロールできるようにすれば、それで事足りる。

> 学生時代の失恋のどん底と、社会人で退職したどん底、絶対値だけ見ると後者の方が高い位置になりかねない、という問題自体は残る。でも別チャートを常設するほどではない。**ユーザーがその時期にズームインすれば、当時の変動幅・谷の深さは普通に見て取れる。** 過剰な指標を増やすより、メインチャートの操作性（ピンチズーム、期間スライダーでの移動など）に力を入れる方が実装コストに見合う。

### (3) 過去の生の言葉の振り返り
辛かった時期に書いた日記本文を、今のチャート位置から読み返せる。「あの時こんなこと書いてたのか、今はもう平気だな」という質的変化は、数値以上に成長を実感させる。

### 落とし穴（設計で必ず避ける）

- 今まさに谷の底にいる人に「成長してます！」と押し付けない。今が底なら、無理に上向きを見せず「谷も人生の一部」と受け止める表示にする
- 成長を演出しすぎて、過去を低く記録し今を高く見せたくなる誘惑（バイアス）を生まない
- アプリが成長を押し付けるのではなく、**本人が振り返って自分で気づける**設計にする

## 7. 画面構成（デザインで作るもの）

### 必須画面（MVP）

1. **日記入力画面** — 文章を書いて送信すると即AI反映。気分スライダーも置く（軽めの日用）
2. **メインチャート画面** — ローソク足。週足/日足切り替え、移動平均、現在値・トレンド・落差などの指標カード
3. **振り返り画面** — 過去の特定日／谷の時期の日記本文と当時のチャート位置
4. **カレンダー／一覧画面** — 記録した日の一覧。ここから各日を開くと編集画面（下記）に入れる

### 副次画面（オプション機能、メイン導線には出さない）

- **編集画面**（旧・確認画面）— カレンダーから該当日を開いた時だけ表示。AIが抽出した出来事カード＋スライダーで微調整（§3参照）

### 後回し（MVP外）

- AIによる自動入力の高度化（しゃべるだけで判定）
- 過去の人生を一括でAIに語って、まとめて過去データを生成する機能
- タグ付け、検索、パスコードロック、テーマ切替、通知

## 8. デザインの方向性メモ

- **OS別に見た目を分ける方針は採用済み**（iOSのLiquid Glass風と、AndroidのMaterialを別々に作る、あるいは独自デザインで統一）。まずは **Android版を最優先でリリース**する
- Adobe（Illustrator等）＋ Figma でデザイン。配色は Adobe Color でパレットを先に決める
- ローソク足が主役なので、**チャートの視認性**を最優先にした配色・余白設計を
- 「ただ書くだけ」の気持ちよさを損なわない、入力画面のミニマルさが鍵

## 9. 技術スタック（決定済み）

- **Flutter**（Windows環境で開発、Android優先リリース、後にiOS）
- ローカルDB：`sqflite` か `hive`
- 状態管理：`Provider` か `Riverpod`
- AI解析：Claude API 等で「日記文章 → 出来事の構造化データ」を抽出

### データモデルの骨子

1日のエントリー：
- 日付
- 日記本文（テキスト）
- 気分スコア（スライダー値・任意）
- 出来事リスト（各：名前／種別[日常・気分・節目]／方向[±]／重み）
- その日のOHLC（始値・高値・安値・終値）— ロジックで算出
- ベースライン値 — ロジックで算出
